多路召回保覆盖、多重排序保精度，如何把对的结果排到第一屏

发表于2026-10-18|更新于2026-10-28
|AILLM
|浏览量:

概述：召回保覆盖，排序保精度

无论搜索引擎、RAG 知识库还是推荐 Feed，从海量候选里挑出"对的那几条"，结构上都是同一座漏斗：先用多种互补的召回策略把候选从百万级快速收缩到千级（宁可多捞不可漏捞），再用逐级变重的排序模型把千级精修到个位数（将最相关、最多样、最合业务的结果排到前面）。

这座漏斗里有两个必须分开的能力，混谈是绝大多数检索系统调不动的根源：

阶段 核心指标 优化目标 算力形态 典型失败
召回 Retrieval 覆盖率（Recall） 找全，别把对的漏在门外 极轻量，索引预计算 该出现的没出现
排序 Ranking 排序质量（NDCG） 找准 + 排好 + 打散 逐条重算，可上重模型 对的出现了却排在后面

一句话记牢：召回决定系统上限，排序决定系统逼近上限的程度。召回漏掉的内容，排序再强也无米下炊；召回捞得够多但排序拉胯，正确结果被埋在第三页。二者用完全不同的技术栈解决，也因此本篇分上下两部：多路召回与多重排序。

先看贯穿全篇的主干漏斗：

flowchart TB
    Q[用户查询] --> U[查询理解 改写与路由]
    U --> R[多路召回 并行发起]
    R --> C1[词面召回 BM25]
    R --> C2[向量召回 稠密双塔]
    R --> C3[晚期交互 ColBERT]
    R --> C4[图谱与结构化召回]
    C1 --> F[融合去重 归一打分]
    C2 --> F
    C3 --> F
    C4 --> F
    F --> P1[粗排 轻量打分]
    P1 --> P2[精排 交叉编码重排]
    P2 --> P3[重排 多样性与业务规则]
    P3 --> OUT[最终结果列表]

漏斗形态不是审美选择，而是算力约束逼出来的：越往下单条打分越贵（双塔内积的千倍到万倍），但候选量也同步降几个数量级，两者的乘积才让整条链路跑得动。“模型重量 × 候选数量” 的守恒关系是贯穿本篇的暗线——理解了它，就知道为什么精排永远只在数百候选上执行，而不是因为"精排应该贵"。

第一部分 多路召回策略：用互补对冲盲区

1.1 为什么要多路：单一召回各有盲区

任何单一召回路本质是一种相似度假设，而假设都会失效：词面匹配假设"用相近的词=问相近的事"，语义向量假设"同一空间夹角能代表相关性"——两者都被现实反复打脸。工程界多年沉淀出的结论是：与其相信一个更强的模型，不如组合几个各有短板的模型，让它们各自的盲区被彼此覆盖。多路召回因此成为标配，各路的强弱对照如下：

召回路 匹配原理 强项 盲区 支撑索引
词面召回（BM25） 稀疏倒排，词频×稀有度 专有名词/型号/代码、可解释 换个说法就失配 倒排索引
稠密向量召回 双塔语义向量比距离 抗词汇失配、语义泛化 低频精确词、领域黑话 ANN（HNSW/IVF）
晚期交互（ColBERT） 多向量 token 级晚交互 细粒度、比双塔准 存储与算力偏重 多向量索引
图谱召回 实体识别后沿关系扩展 多跳、关系类问题 抽取成本、覆盖有限 知识图谱
结构化召回 元数据/标签/SQL 过滤 精确、权限时间可控 无语义，需字段齐 B+树/标量索引
行为召回（推荐） 协同/共现/i2i 挖掘隐式偏好、惊喜度 冷启动、语义无关 倒排/向量

1.2 词面召回：BM25 与稀疏家族

词面召回是最老也最不可替代的一路。它的代表 BM25 在一个词的 posting list 上打分，同时考量词频（TF，饱和增长）、逆文档频率（IDF，越稀有的词越有权重）、文档长度归一：

$$
\mathrm{BM25}(q,d)=\sum_{i=1}^{n}\mathrm{IDF}(q_i)\cdot\frac{f(q_i,d),(k_1+1)}{f(q_i,d)+k_1\left(1-b+b\cdot\frac{|d|}{avgdl}\right)}
$$

两个参数的直觉：$k_1$ 控制词频饱和速度（越大越奖励多次命中），$b$ 控制长度惩罚强度（0 不惩罚、1 完全按比例）。它的价值在精确词面——型号 HZ-2040、错误码、法律条款号、人名，这些在语义空间里几乎没有存在感的低频 token，恰是 BM25 的主场。

倒排索引的查询形态是"每个 query 词对应一条 posting list（文档 ID、词频、位置的有序链），求交集后逐条算分"。麻烦在于常见词的 posting list 可达百万长，全量遍历会拖垮整条链路。WAND 这类动态剪枝是工业标配：给每个词维护一个"它最多能贡献多少分"的上界，用堆顶候选与剩余上界之和比较——跳过长到不可能进入 Top-K 的文档，甚至直接跳到必查词。于是 BM25 慢于向量检索的印象被反转：剪枝后的词面召回在 CPU 上就能做到万级 QPS，这是混合召回里它始终占一路的底气。

稀疏家族近年复兴：SPLADE 用模型给每个词预测一个扩展权重，把"语义扩展"做进了稀疏表示（同义词也被赋权），既保留倒排索引的可解释与精确匹配，又蹭到语义泛化，是很多"混合召回"里的新稀疏路。

1.3 稠密向量召回：双塔与近邻检索

稠密召回把 query 和文档各自编码为一个向量，比较夹角：

$$
s(q,d)=\cos(\mathbf{e}_q,\mathbf{e}_d)=\frac{\mathbf{e}_q\cdot\mathbf{e}_d}{\lVert\mathbf{e}_q\rVert,\lVert\mathbf{e}_d\rVert}
$$

关键在于双塔（Bi-Encoder）结构：文档塔离线把全库向量灌进 ANN 索引，query 塔在线只算一次向量，再让近邻引擎（HNSW 多层图、IVF 分桶）在毫秒内返回 Top-K。它把"相关性"变成了"检索距离"，天然抗词汇失配——问"发票抬头怎么改"能召回"开票信息变更流程"。

盲区同样明确：向量是独立编码的（文档不知道谁在问它），对"两个只差一个数字的型号"分辨力弱，且高度依赖训练语料的领域覆盖。这决定了它必须和 BM25 结伴。

训练上，双塔用对比学习塑造空间：把 query 与其正确文档作为正例对、把同 batch 内其它文档当批内负例推开，再叠加难负例挖掘（捞那些"语义很近却不相干"的硬样本）。领域黑话召不回，多半是训练里没见过对应正负例，而非模型容量不够。

索引侧还有一层绕不开的成本：HNSW 把原始向量全部常驻内存，亿级 768 维浮点单副本就是几百 GB。所以 ANN 之后紧跟着量化：PQ 把向量切成若干子空间、每个子空间独立聚类后用码字下标代替原始浮点；OPQ 先做一次正交旋转再切分，找到"对切分友好"的坐标系。量化省内存但损精度，工程上靠"量化码粗筛 + 原始向量重排"补回来——同一套"粗排砍量、精排校准"的思想在索引内部的递归出现。

1.4 晚期交互召回：ColBERT 的两全之道

双塔快但糙，cross-encoder 精但慢（详见第二部分）。ColBERT 走中间路线：为每个词元生成一个向量，query 与文档的相关性用 MaxSim——query 的每个词元向量找文档中最像它的词元取最大值再求和：

$$
s(q,d)=\sum_{i=1}^{|q|}\max_{j=1}^{|d|}\mathrm{sim}!\left(\vec{q}_i,\vec{d}_j\right)
$$

它保留了 token 级细粒度交互（比单向量双塔准得多），又能把文档多向量离线预存、在线只做轻量 late interaction。代价是存储膨胀（每文档 N 个向量），靠**残差量化（PQ 类压缩）**把它压回可用水位（残差编码只存与原向量的差值再量化，精度损失远小于直接量化）。定位：既要召回质量、又要比 cross-encoder 便宜的中间精排/召回层。

1.5 图谱召回与结构化召回

图谱召回处理"跨文档多跳"和"关系类"问题：先做命名实体识别，定位图谱中的实体节点，再沿关系边扩展一跳，把相连的实体/文档一起捞回。它能回答"A 公司 CEO 的母校在哪"这类单次向量检索拼不出的链条（配合 GraphRAG 的全局归纳）。短板是实体关系抽取的离线成本与覆盖率。

图谱路有两个只有真正建过图才会踩的坑。其一是实体链接歧义："苹果"是公司还是水果，取决于上下文，链接落错节点则整条关系链全错；其二是超级节点——某些实体（常见人名、平台级公司）挂着百万条边，一跳扩展直接淹没候选池。所以图扩展必须同时约束跳数与每跳的边权重截断，必要时按度数剪枝：图谱召回的收益来自精确的窄链路，来自宽度的只有噪声。

结构化召回是最朴素却最常被低估的一路：把时间、部门、产品线、权限、语言等抽出为标量字段，检索前先过滤再比较向量。它解决两类向量永远解决不了的问题——“2025 年的政策”（年份不在语义向量里）和"我只能看本部门文档"（权限是硬约束）。任何生产级检索都需要一条元数据过滤通道兜住这两件事。

1.6 行为与协同召回（推荐场景）

在推荐 Feed 里，召回逻辑从"匹配查询"变成"匹配用户"。经典并行多路：

  • 热度召回：全局/分类热门榜，兜底与冷启动；

  • 内容相似（i2i）：基于物品共现或内容标签，“看了又看”；

  • 协同过滤 / 双塔 u2i：用户塔×物品塔算近邻，挖掘隐式偏好；

  • 序列召回：用用户行为序列建模兴趣迁移（类 SASRec）；

  • 探索召回：随机/新内容/多样性注入，对抗信息茧房。

这套思路与文本检索可互相借鉴：RAG 里的"多视角查询扩展"本质就是"一个 query 的多路 i2i"。

共现相似度不能直接用计数：热门物品与任何物品都共现，"买了它的人也都买了它"毫无区分度，所以要除以两边频次的开方（ItemCF 的余弦修正）；再进一步，两个用户只在同一订单里买过同一对商品就会互相加权，刷量团伙可以人造出热门共现——Swing 用"用户-物品对"的扇形结构给这类巧合降权：共同邻居越集中，权重越低。行为路的隐性成本是更新频率：i2i 表要天级甚至小时级重算，否则新物品永远进不了候选，冷启动与时效性是同一条链路的两端。

1.7 多路融合：怎么把几份榜单并成一个

多路各自返回 Top-K，但不同路的分数不可直接比（BM25 可能是 12.7，余弦是 0.81），融合要处理量纲与冲突。四种主流做法：

策略 机制 优点 风险
加权求和 各路分数先归一再按权相加 简单、可调 对归一化敏感，权重靠拍
倒数排名融合 RRF 只看名次不看分值 天然规避分数不可比 丢失分数间距信息
模型融合 学习最优合并策略 上限高 需标注数据
交错合并 各路轮流取一条 保底覆盖每一路 相关性次序弱

加权求和必须先归一化，常用 z-score 或 min-max：

$$
z(s)=\frac{s-\mu}{\sigma},\qquad \mathrm{score}(d)=\sum_{i} w_i\cdot z_i!\left(s_i(d)\right)
$$

RRF（倒数排名融合） 是工程首选，只用每路的排名、不碰分值，$\mathcal{R}$ 为所有召回路集合，$k$ 通常取 60（抑制头部权重）：

$$
\mathrm{RRF}(d)=\sum_{i\in\mathcal{R}}\frac{1}{k+\mathrm{rank}_i(d)}
$$

融合后必须去重：同一文档被多路命中只留一条（且往往是最强信号——多路共现本身就说明它相关）。

融合层还有三个旋钮决定它的上限。候选深度对齐：各路 TopK 不同则 RRF 尾段天然缺项，通常把各路统一补到一个整数（向量路 200、词面路 200，融合后截到 350），或按各路历史 Recall 贡献动态分配深度。重复消除：同一文档的不同切片、父子块的多个子块都在候选里各占一位，去重键应是文档 ID 而非块 ID。权重从哪来：$w_i$ 最稳的求法是网格搜索——在 golden set 上扫出一组融合权重、再用线上 A/B 定；冷启动阶段用等权 RRF 兜底（它不依赖任何权重），攒够日志再升级到加权和与模型融合，这条"先 RRF 后学习融合"的演进路径几乎不需要返工。

1.8 查询路由：动态决定开哪几路

并非每条 query 都值得开满所有路。轻量分类器/规则把 query 分流：含专有名词走词面加权、口语化走语义加权、带时间地点走元数据过滤、多跳意图走图谱。查询路由既省算力，又能对不同意图施加不同的融合权重——这是"多路召回"从静态堆料进化成动态编排的关键一步。

路由器本身要做得便宜：实践上常用正则抓"含数字串/大写字母/型号格式"直接上调词面权重，用一个几百样本训练的小分类器判"是否是关系链问题"决定是否开图谱路，而不是每条 query 都叫一次大模型——路由的开销必须比它省下的开销小两个量级，否则路由本身就成了瓶颈。另一个工程直觉：路由失败要能兜底，判错意图至少应该退回到"默认开双路 + RRF"，而不是退回到单路。

第二部分 多重排序算法：三级漏斗逐级变重

召回给出的是"一堆大致相关的候选"，排序要回答的是"谁排第一、第二、第三，且这屏结果整体好不好"。生产系统几乎都是三级漏斗，越往下候选越少、模型越重、目标越贴近最终体验：

flowchart TB
    A[候选 百万级 全库] -->|多路召回| B[万级 各路并集]
    B -->|融合去重| C[数千级 精排候选]
    C -->|粗排| D[数百级]
    D -->|精排| E[数十级]
    E -->|重排| F[最终 5到10条]

2.1 粗排：轻量打分从千级砍到百级

精排模型（cross-encoder）逐条打分太贵，不可能对数千候选全量执行。粗排用极轻的模型（双塔向量内积、几个统计特征的浅层模型、或 ColBERT 这类晚期交互）把数千砍到数百，只求"别把该进精排的好东西砍掉"，允许一定排序误差。它是精排的高性价比前置过滤器——用 5% 的算力砍掉 90% 的候选。

粗排的训练目标有个反直觉的选择：不学点击，学精排的输出。点击日志自带位置偏差，拿它训粗排会把偏差一并学进去；而让精排模型当"教师"给候选打伪标签、粗排做蒸馏拟合（即"一致性训练"），两层的目标就不打架——粗排的职责不是判得准，而是与精排判得一致，宁不得罪真相关，不可漏送精排要看的候选。

2.2 精排：Cross-Encoder 与相关性建模

精排是排序质量的顶梁柱，主力模型是 Cross-Encoder：把 query 和候选拼在一起送进 Transformer 做全交互自注意力，逐对输出一个相关性分：

flowchart LR
    subgraph DE[双塔 独立编码 快而糙]
        Q1[查询塔] --> VQ[查询向量]
        D1[文档塔] --> VD[文档向量]
        VQ --> S1[向量内积]
        VD --> S1
    end
    subgraph CE[交叉编码 全交互 准而慢]
        Q2[查询文本] --> J[拼接输入同一模型]
        D2[文档文本] --> J
        J --> S2[逐对相关性分]
    end

两者的分野就在交互时机：双塔的文档编码"看不见" query，只能靠最终一个向量硬压全部语义；cross-encoder 让 query 的每个词与文档的每个词在层内反复 attend，能捕捉词级精确匹配，代价是每对一个前向、无法预计算，所以只用在候选已被砍到百级之后。

精排的打分不止语义相关性。多路特征加权是常见做法：

$$
\mathrm{score}(d)=\alpha\cdot\mathrm{rel}(q,d)+\beta\cdot\mathrm{auth}(d)+\gamma\cdot\mathrm{fresh}(d)+\delta\cdot\mathrm{ctr}(d)
$$

$\mathrm{rel}$ 来自 cross-encoder，$\mathrm{auth}$（权威性）、$\mathrm{fresh}$（时效）、$\mathrm{ctr}$（历史点击）等业务信号按权重融合——这也是"排序"区别于"纯检索"的地方：它要的是综合最优，不是单纯语义最像。

2.3 Learning to Rank：让模型学会"排"而非"分"

用绝对分回归相关性往往不佳——排序真正在意的是相对次序，不是分数本身。Learning to Rank（LTR）正是围绕这一点设计的三大范式：

范式 建模对象 代表算法 特点
Pointwise 单条文档打绝对分 回归 / 分类 简单，忽略文档间关系
Pairwise 文档对的相对优劣 RankNet、LambdaMART 贴近排序，业界主力
Listwise 整个列表的损失 ListNet、Soft-Rank 直接优化 NDCG，最贴目标

Pairwise 把排序化为"任意两条谁在前"的二分类，RankNet 用分数差的 sigmoid 拟合偏序概率、以交叉熵训练：

$$
P_{ij}=\sigma(s_i-s_j),\qquad
\mathcal{L}=-\sum_{(i,j)}\left[\bar{P}{ij}\log P{ij}+(1-\bar{P}{ij})\log(1-P{ij})\right]
$$

LambdaMART 在此之上加了关键一招：不直接对每个梯度做优化，而是给每条文档赋一个 $\lambda$（它换位会引起的 NDCG 变化量），让梯度优先修正"影响排序指标最多的那几对"——因为 NDCG 对 pairwise 损失不可导，Lambda 是绕过不可导、把优化对准指标的桥梁。

Listwise 更激进，直接对整个排列建模。这类模型（含 LLM 排序）用 NDCG 作最终评估锚：

$$
\mathrm{NDCG}@K=\frac{\mathrm{DCG}@K}{\mathrm{IDCG}@K},\qquad
\mathrm{DCG}@K=\sum_{i=1}^{K}\frac{2^{rel_i}-1}{\log_2(i+1)}
$$

分母的 $\log_2(i+1)$ 就是"位置折扣"——排得越靠后，贡献越小；IDCG 是理想排序的 DCG，用来归一到 [0,1]。

LTR 落地有两个隐蔽陷阱。其一，训练信号来自点击日志或 golden 标注，而点击自带位置偏差（排前面的天然被点得多），需用随机曝光日志或 IPS 逆倾向加权去偏，否则模型只会学到"复制现有排序"。其二，精排模型离线训好、在线打分，训练与线上的特征必须严格一致——特征穿越（用了预测时点之后才可得的信息）是最难排查的质变杀手。

还有一个容易被指标掩盖的坑：Pairwise/Listwise 损失只教模型"排对次序"，输出的 $s$ 是相对分、不具备概率含义——它会随数据分布漂移，因此不能拿来判"这条到底相不相关"（比如上下文污染所需的低分截断）。判阈值要另走一路：在同一样本上并行拟合一个校准头，或干脆用 Pointwise 交叉熵模型。排序与判别是两件事，一个模型同时做二者往往两头都失真。

2.4 LLM 作为排序器

大模型给排序带来新范式：把 query 和候选编号一起塞进提示词，让模型输出一个相关性排列——RankGPT 式生成排序（滑窗取 Top、逐段重排）或让模型逐条打分的pointwise 判别。优点是零样本强、能理解复杂意图与长文档；缺点是延迟高、贵、位置偏差敏感（倾向给靠前排的高分，需打乱多次取平均）。工程定位：适合候选已很少的高质量精排/重排层，或用于给 LTR 蒸馏生成训练标注。

位置偏差的治理有专门一招：Permutation Distillation——把同一批候选随机打乱多次、让模型分别排序，再对每个候选取平均名次，或把这批"大模型判出的排列"蒸馏进一个小 cross-encoder。前者用采样抹平方差，后者把贵的判断力变成便宜的离线资产，两种做法都针对同一个事实：LLM 对输入顺序敏感，一次输出的排列不足以作为标注。

2.5 重排：多样性与全局最优

精排按分从高到低直排，会带来"前 10 条长得一模一样"的问题——同主题、同来源刷屏。相关性只是逐条最优，用户满意的是整屏最优，重排（re-ranking）处理的就是这个从局部到全局的跨越。

MMR（最大边际相关） 是最常用的边选边去冗余准则，每选一条都在"相关"与"和已选集合不重复"间权衡：

flowchart LR
    CAND[候选池] --> RE[相关性项]
    SEL[已选集合] --> SIM[与已选最大相似度 冗余项]
    RE --> MM[MMR 目标 相关减冗余]
    SIM --> MM
    MM --> PICK[取最优加入已选]
    PICK --> SEL

$$
\mathrm{MMR}=\arg\max_{d_i\in R\setminus S}\left[\lambda\cdot\mathrm{sim}(d_i,q)-(1-\lambda)\cdot\max_{d_j\in S}\mathrm{sim}(d_i,d_j)\right]
$$

$\lambda=1$ 退化为纯相关性排序，越小越强调多样。

DPP（行列式点过程） 比 MMR 更进一步，用一个核矩阵的子式行列式为整个集合的质量打分——几何上行列式等于这些向量张成的平行体体积，向量越不共线（越多样）体积越大：

$$
P(\mathcal{Y})\propto\det\left(L_{\mathcal{Y}}\right),\qquad L_{ij}=r_i,r_j,S_{ij}
$$

$r$ 是每条的质量、$S$ 是两两相似度，可分解 DPP 把"高质量"与"低冗余"统一进一个全局最优目标，避免 MMR 贪心的次优。

除了算法化多样性，重排层还叠加一堆业务规则：同作者/同域名打散（滑窗降权）、类目配额、去重合并、已读过滤、新鲜度保量、强规则置顶与合规降权。这层往往是"运营可干预"的最后一公里。

再往上一层是列表级建模：MMR 与 DPP 都在"逐条加约束"，而工业系统会直接建模整屏价值——生成式重排（PRM、序列生成类）对候选的排列打分，评估不同排列下的期望点击，再取最优排列。它的动机是一个行为学事实：位置之间存在相互影响（同屏竞品互相分流注意力），逐条最优之和并不等于整屏最优，这也是"相关性只是逐条最优、用户满意的是整屏最优"的技术版本。

2.6 分数校准与多目标融合

排序各目标（相关、点击、时长、转化）来自不同模型，分值不在同一量纲，直接相加会失真。校准把模型输出映射成可解释的概率——Platt Scaling（对 logit 拟合一条 sigmoid）或 Isotonic 回归是最常见两种：

$$
P(y=1\mid s)=\frac{1}{1+e^{-(As+B)}}
$$

校准后才能做多目标融合排序（如 $\mathrm{score}=\mathrm{rel}^{w_1}\cdot\mathrm{ctr}^{w_2}\cdot\mathrm{auth}^{w_3}$ 的乘式融合，或加权）。推荐系统的**精排多目标（MMoE/ESMM 之类）**本质也是这套"先校准再融合"，只是目标更多。

第三部分 评估、场景配方与工程落地

3.1 分层评估指标

召回和排序的失败模式不同，必须分层度量，否则调优是蒙眼：

层级 指标 度量什么
召回 Recall@K、命中率 正确结果进没进候选
排序 MRR 第一条正确结果排得多前
排序 NDCG@K 带位置折扣的整体排序质量
排序 MAP 多相关场景下平均精度
重排 多样性（ILD/熵）、重复率 整屏是否刷屏冗余
业务 CTR、解决率、停留 用户真实买不买单

关键前提仍是 golden set：人工标注一批"每个 query 的正确来源及其相关等级"，任何召回/排序/融合改动都必须先离线跑过基线再上线，badcase 永久进回归集。

MRR 只看第一条正确结果的位置，$\mathrm{rank}_i$ 是第 $i$ 个 query 的首条正确结果名次：

$$
\mathrm{MRR}=\frac{1}{|Q|}\sum_{i=1}^{|Q|}\frac{1}{\mathrm{rank}_i}
$$

对"只有一条标准答案"的问答场景，它比衡量整屏质量的 NDCG 更敏感。

两个指标的分工要拎清：Recall@K 只问"对的东西在不在候选里"，不看位置；NDCG@K 给位置加权，同一份候选换个排法 Recall 不变而 NDCG 会变。所以 Recall@K 归召回管、NDCG 归排序管，两条基线必须分开维护——只用一个端到端指标（比如最终答案正确率）会让"该动召回还是该动排序"的判断重新变回拍脑袋。

多样性也需要可度量的口径，否则重排调参同样凭感觉：常用 ILD（结果集内两两相似度的均值，越低越多样）、列表内主题/来源熵、以及路覆盖率（Top 结果来自几路召回）。路覆盖率是个廉价却灵敏的信号：若前 10 条全部来自向量路，说明融合权重失衡、词面路的精确命中被埋没了。

3.2 三类典型场景配方

同样的积木，不同场景配比不同：

场景 召回组合 融合 排序配方
RAG 问答 BM25 + 稠密向量 + 元数据过滤 RRF 粗排砍量 → cross-encoder 精排 → MMR 去冗余，Top3~5
网页搜索 词面 + 语义 + 图谱 + 行为点击 归一加权 强精排 + 权威/时效特征 + 域名打散
推荐 Feed 热度 + i2i + 双塔 u2i + 序列 交错保量 多目标精排（CTR/时长）+ DPP 多样重排

RAG 检索增强生成为什么效果差？如何按三段逐环节治理误区 里的"两级漏斗"正是这里精排+重排的裁剪版：全库→（向量+BM25）→Top50~100→（cross-encoder）→Top3~5，本质是同一套漏斗在问答场景的落地。

以一次典型 RAG 检索走完整条预算：全库 200 万块，BM25 与向量各取 200、RRF 去重得约 350 候选；粗排砍到 60；cross-encoder 逐条精排取 12；MMR 重排后留 5 条进上下文——每一级候选规模大致按 10 倍收敛，这正是"越往下模型越重却仍跑得起"的根本原因。

3.3 工程落地清单

  1. 起步先上 BM25 + 稠密向量双路 + RRF，这一步能解掉大半"搜不到"，别一上来堆六路；

  2. 各路分数融合前必须归一化，或直接改用只看名次的 RRF 绕开量纲问题；

  3. 精排候选量与算力挂钩：先上粗排把数千砍到数百，再让 cross-encoder 精排；

  4. 排序质量用 NDCG、召回质量用 Recall@K 分开看，别用一个端到端指标掩盖漏斗某段的塌陷；

  5. 结果刷屏时再引 MMR/DPP，别在没验证相关性够好前就调多样性；

  6. 建立 golden set 与 CI：换 embedding、调融合权重、改排序模型都先过基线；

  7. 查询路由按需开路与加权，控制长尾 query 的算力浪费；

  8. 重排层预留业务规则开关（打散、置顶、配额），让运营能干预最后一公里。

3.4 四种高频翻车模式

清单只能防已知问题，下面四种是"数据看起来都对、系统却越调越差"的典型形态，各自对应一个反直觉的结论：

翻车现象 真实原因 反直觉结论
换更强 embedding 后 Recall@K 没变，投诉却变多 新模型把无关内容也召回了，精排顶不住噪声 召回不是越多越好，候选变脏会污染下游
单路都能召回到正确文档，融合后它反而出局 RRF 只看名次，弱路的尾段名次太低、被强路头部压制 多路共现才是强信号，单路高分不一定可靠
上了 cross-encoder 精排后 P95 延迟爆表 忘了先上粗排，千级候选逐条前向 精排的前提是有人替它砍量
离线 NDCG 涨、线上 CTR 跌 训练特征穿越，或 LTR 只复制了历史排序的位置偏差 离线指标的涨可能只是在复述旧策略

四种形态共同的根因只有一个：漏斗是一体的，单点指标的改善不等于端到端改善。每次只动一层、每层各自有基线，才不会把"调优"变成"调运气"。

总结

多路召回与多重排序是同一座漏斗的两半：召回用一组各有盲区的相似度假设互相兜底，把"可能对"的都捞进来定住上限；排序用逐级变重的模型和从相关到多样到业务的连续权衡，把上限兑现成排在前面的那几条。

技术选型可以浓缩成三句判断：搜不到先动召回（加词面路、加语义路、上混合与元数据过滤）；排不对先动精排（cross-encoder、LTR 的 LambdaMART、特征融合）；看着腻就动重排（MMR/DPP 打散 + 业务规则）。把这三句和分层指标固化进 CI，检索系统才从"能搜出东西"进化成"稳定把对的东西排在第一屏"。
