剧本变分镜还要人肉拆？用 PenShot 智能体把长剧本拆成 5 秒级视频片段

现在的 AI 视频模型（可灵、即梦、Veo 这一类）基本只吃 5 秒级短片段，而一部短剧的剧本动辄几十场戏。把剧本拆成"每个镜头 5 秒、角色形象前后一致、场景衔接连贯"的分镜脚本，是标准的导演级手工活——也是 PenShot 要自动化的那一环。

PenShot 是一个基于 LangGraph 的剧本分镜智能体：输入任意长度的剧本，输出可直接投喂给 AI 视频模型的分镜片段。v0.4.x 内部由八个顺序执行的智能体节点组成流水线（早期版本为六节点，0.4.2 加入资产计划、0.4.3 加入模型路由），每个节点"接收输入 → 调用 LLM 或规则 → 结果判定 → 进入下一节点或触发修复"。本文讲清楚三件事：怎么跑起来、流水线内部发生了什么、它擅长什么不擅长什么。

一、两条部署路径

路径 A：pip 安装

路径 B：Docker（推荐，环境隔离）

两类密钥通过环境变量注入（也可用 .env 文件，不要写进配置文件提交到仓库）：PENSHOT_LLM__DEFAULT__* 负责生成，PENSHOT_EMBED__DEFAULT__* 负责向量化。服务起在 8000 端口，提供 REST 接口；SDK 与 MCP 协议三条接入链路的差异在文档中心有专门对比。

二、八个智能体节点：流水线内部发生了什么

PenShot 把"剧本 → 分镜"拆成八个职责单一的节点，由 LangGraph 负责端到端协调：

节点 输入 → 输出 关键处理
剧本解析 原始文本 → 结构化剧本 格式自动识别 + LLM 提取场景/角色/元素 + 完整性评分
资产计划 结构化剧本 → 资产生成规格 角色三视图 / 道具 / 场景资产声明，默认不直接出图
镜头拆分 结构化剧本 → 镜头序列 元素分组（对话合并规则）+ 三类时长估算器
视频分段 镜头序列 → 视频片段 超阈值镜头 LLM 语义切分 / 规则均分，保持连续性
提示词转换 视频片段 → 生成指令 产出可直接投喂视频模型的提示词
模型路由 生成指令 → 目标模型方案 按片段选择目标模型，输出 route_plan 与模型专属提示词
质量审计 生成指令 → 审计报告 规则校验，问题项回流修正
连贯性守护 全局视角审查 跨片段的角色/场景一致性检查

各节点的输入输出模型（ParsedScript、AssetPlan、ShotSequence、FragmentSequence、AIVideoInstructions、QualityAuditReport）都是强类型的 Pydantic 模型——节点之间传的不是松散字符串，而是可校验的数据结构，这是流水线能稳定修复回流的基础。

flowchart TD

    B --> C{完整性评分达标?}
    C -- 否 --> B
    C -- 是 --> B2[资产计划<br/>角色/道具/场景规格]
    B2 --> D[镜头拆分<br/>元素分组+时长估算]
    D --> E[视频分段<br/>超长镜头语义切分]
    E --> F[提示词转换<br/>生成视频模型指令]

    G -->|问题项| F

    H -->|漂移风险| F
    H -->|通过| I[分镜片段输出<br/>提示词 + 资产计划 + 路由结果]

值得注意的设计是两个回流环：质量审计发现问题退回提示词转换，连贯性守护发现漂移风险同样退回对应来源节点——生成质量不是靠一次调用赌出来的，而是靠校验层兜出来的。0.4.4 起，回流会按问题的来源阶段路由，而不是一律重跑分镜。

三、一致性约束：结构化字段是主通道，检索是增强

短剧最怕的是"角色漂移"：同一个角色在第 3 场和第 30 场长了两张脸。PenShot 的主解法不是让 LLM 自己记，而是把约束结构化，每站都带着走：

  1. 全剧上下文：解析阶段产出角色服装、关键道具、场景地点与连续性要点，指令转换时按固定段落注入每个片段的提示词；

  2. 一致性契约：跨块契约（GlobalConsistencyContract）把角色外观、场景与风格约束传给资产计划与提示词转换；

  3. 声明式资产：角色三视图、道具静帧、场景图以 character_sheet / prop / scene 规格声明，下游生成后可用首帧或参考图约束画面；默认不直接出图。

模板库的锚点召回是可选增强：按角色/场景锚点检索历史成功提示词，命中就作为参考注入，未命中也不报错。它提高一致性概率，但不是"必然命中"的保证。三层记忆（Redis / 摘要 / Chroma）确实存在，不过记忆的语义读取链路尚未接入生成上下文——能写不等于会用，这一点要按实际产物验证。

一句实话：如果下游不执行资产计划、也不使用 asset_ref 首帧，角色外观仍会漂移。文本约束降低概率，参考图/首帧才真正"锁形"。

四、走读一遍：30 场戏短剧的拆解过程

用一个具体例子串起整条流水线。输入：一部 30 场戏、3 个主要角色的都市短剧剧本，约 2 万字。

第一站·剧本解析。格式识别判断出这是标准剧本格式，LLM 提取出场次结构、3 个角色的档案、关键道具，并对解析结果做完整性评分——角色是否有外貌描述、场景是否有环境要素。假设评分发现"反派角色的外貌描述缺失"，回流让 LLM 从对白与动作描写里补全，评分达标后输出结构化剧本。这一步决定了后面所有环节的质量上限。

第二站·资产计划。按角色、道具、场景生成资产生成规格：角色三视图要有哪些视角、服装材质如何描述、哪些片段会用到哪个资产。PenShot 默认只给规格与提示词，不直接调用文生图；下游生成后可回传 asset_manifest，把真实引用接回片段。

第三站·镜头拆分。按叙事节奏与对话合并规则把 30 场戏拆成镜头序列，三类时长估算器给每个镜头估时长——对话多的场面按台词密度估，动作场面按节奏估，过渡镜头按经验值估。

第四站·视频分段。超过阈值的镜头进入二次处理：语义完整的走 LLM 切分（保持动作连续性），适合机械切分的走规则切分。0.4.5 起片段时长改为按动作节点确定性推算，规则切分不再简单均分，输出带总时长偏差报告。

第五站·提示词转换。每个片段结合全剧上下文与资产引用生成视频模型指令——"第 14 镜，女主在雨夜便利店门口，暖光，近景 5 秒"这样的结构化描述被转成可灵/即梦们真正吃的提示词格式。

第六站·模型路由。按片段的可读文字、镜头复杂度、角色一致性需求与时长，选择 runway_gen4 / kling_3 / luma_dream / sora_2 / pika_2 之一，输出 route_plan 与模型专属提示词包。路由失败只告警，不阻断主流程。

第七站·质量审计 + 第八站·连贯性守护。审计器做规则校验（字段完整、时长合规、提示词自洽、资产引用有效），守护器做跨片段检查（女主在第 3 镜和第 27 镜的服装是否一致）。任一环节出问题，按来源节点退回重生成；0.4.4 起跨场景跳变会用确定性过渡镜头修复，而不是反复重跑分镜。

全程对 LLM 的调用次数与剧本规模成正比——30 场戏意味着流水线要走几百次模型调用。检查点落盘对长剧本因此不是优化项而是必需品；但在 v0.4.5 的续传入口接通之前，控制单次成功率（降并发、分批、选稳定供应商）比"指望中断后自动续跑"更实际。

五、排障清单：三个最常见的卡点

按真实使用中出现的频率排序：

现象 根因 处理
解析评分反复不达标 剧本本身信息缺失（角色无外貌、场景无描述） 先人工补全剧本骨架再跑，或换更强的 LLM
中途 LLM 超时/限流 长剧本的调用密度高，撞上供应商限流 降低并发、按批提交；检查点只落盘状态，续传入口截至 v0.4.5 未接通，中断后仍需从头执行
模板召回不命中、约束没生效 Embedding 质量差或维度不匹配，或下游没有执行资产计划 核对 PENSHOT_EMBED__DEFAULT__* 配置与模型文档；确认资产/首帧引用是否真的接进生成

第三条值得展开：一致性约束的主通道是结构化字段（全剧上下文、一致性契约、资产计划），模板锚点召回只是增强层。Embedding 配置错了（维度不匹配、模型质量差），召回会静默不命中——不报错，只是少了一层参考；如果下游又没执行资产计划，角色换脸就会真的发生。排查入口是官方文档中心的知识库与召回、记忆与检索两节。

六、工程边界：它擅长什么、不擅长什么

基于 v0.4.5 源码复核的结论，说清楚边界比吹能力更有用：

  • 擅长：叙事连贯的长剧本拆解、角色一致性要求高的连续剧、需要批量产出提示词与模型路由方案的流水线场景

  • 不擅长：需要精确到帧的动作编排（这仍是导演的活）、对单镜头画面质量有极致要求的场景（取决于底层视频模型）

  • 依赖现实：生成质量与所配 LLM 强相关——解析、拆分、转换每一步都在调 LLM，模型能力直接决定下限；Embedding 质量影响模板召回命中率，但它只决定"增强层"的厚度，一致性下限由结构化字段与资产执行决定

另一个需要说清的能力：工作流检查点。八节点流水线跑几十场戏不是秒级的事，检查点确实会把每步状态落盘；但截至 v0.4.5，恢复入口仍未接通——每次执行的 thread_id 都是新的，服务中断后无法命中历史快照从断点续跑，只能从头开始。落盘状态目前的实际价值在事后排障与产物复盘。机制细节与最小修复路径见断点续传实战复盘。

文档中心对每一环都有源码级展开。

七、三条工程结论

  1. 一致性靠结构不靠祈祷：把角色外观、服装、场景写成结构化字段随每站传递，再叠加可选召回与首帧参考——一致性靠数据约束，不靠提示词手气，这个思路在任何多片段生成场景（漫画、绘本、广告片）都可复用；

  2. 强类型数据契约是智能体流水线的地基：节点间传 Pydantic 模型而不是自由文本，校验和修复才有抓手；

  3. 先跑通边界内的场景：长剧本、强一致性、批量产出是它的主场；单镜头极致画质请直接把预算花在视频模型上。
