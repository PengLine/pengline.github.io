剧本变分镜还要人肉拆？用 PenShot 智能体把长剧本拆成 5 秒级视频片段

现在的 AI 视频模型（可灵、即梦、Veo 这一类）基本只吃 5 秒级短片段，而一部短剧的剧本动辄几十场戏。把剧本拆成"每个镜头 5 秒、角色形象前后一致、场景衔接连贯"的分镜脚本，是标准的导演级手工活——也是 PenShot 要自动化的那一环。

PenShot 是一个基于 LangGraph 的剧本分镜智能体：输入任意长度的剧本，输出可直接投喂给 AI 视频模型的分镜片段，用六段工作流保证结构完整，用三层记忆压制角色与场景漂移。本文讲清楚两件事：怎么跑起来，以及它擅长什么、不擅长什么。

一、两条部署路径

路径 A：pip 安装

路径 B：Docker（推荐，环境隔离）

两类密钥通过环境变量注入（也可用 .env 文件，不要写进配置文件提交到仓库）：PENSHOT_LLM__DEFAULT__* 负责生成，PENSHOT_EMBED__DEFAULT__* 负责向量化。服务起在 8000 端口，提供 REST 接口；SDK 与 MCP 协议三条接入链路的差异在文档中心有专门对比。

二、六段工作流：输入剧本，输出分镜

PenShot 把"剧本 → 分镜"拆成六段流水线，每段职责单一、可单独检查：

  1. 剧本解析：识别场次、人物、场景与对白结构

  2. 任务拆解：按叙事节奏切分待生成单元

  3. 分镜规划：为每个单元确定镜头语言与时长（5 秒级）

  4. 一致性注入：从三层记忆中取角色 / 场景 / 风格约束写入提示词

  5. 提示词生成：产出可直接使用的视频模型提示词

  6. 质量检查：对成稿分镜做规则校验与回流修正

其中三层记忆是压制"角色漂移"的关键：同一个角色在第 3 场和第 30 场必须长一张脸，靠的不是提示词里反复描写，而是记忆层把角色卡、场景卡、风格卡结构化存取，按需注入。

三、工程边界：它擅长什么、不擅长什么

基于 v0.3.x 源码实测的结论，说清楚边界比吹能力更有用：

  • 擅长：叙事连贯的长剧本拆解、角色一致性要求高的连续剧、需要批量产出提示词的流水线场景

  • 不擅长：需要精确到帧的动作编排（这仍是导演的活）、对单镜头画面质量有极致要求的场景（取决于底层视频模型）

  • 依赖现实：生成质量与所配 LLM 强相关；Embedding 质量影响记忆检索精度

文档中心对每一环都有源码级展开，重点推荐这几篇：

  • 节点详解：六大智能体的源码实现与规则逻辑

  • 一致性策略：多片段生成如何压制角色与场景漂移

  • 检查点：工作流状态落盘与断点续传

  • 召回评测：三层记忆真机实测与评测方法论
